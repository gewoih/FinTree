# Личный финансовый советник поверх FinTree — дизайн

Дата: 2026-11-16 · Статус: на согласовании

> Репозиторий публичный. В этом документе нет личных цифр владельца. Все личные данные (доход, цели,
> ценности, портфель) — в `.claude/finance/profile.md`, папка в `.gitignore`.

## 1. Зачем

Владелец FinTree годами записывает траты через Telegram-бота и раньше сам разбирал месяц на сайте.
Сайт показывает много графиков и цифр, но интерпретация остаётся на человеке, и он «сам себя защищает»:
видит цифры и находит им объяснение. Когда пропал стабильный доход, разборы прекратились.

Нужен личный ИИ-советник, который:
- сам по расписанию смотрит на траты и говорит человеческим языком: всё ли в порядке и куда двигаться;
- держит курс на долгосрочную цель (финансовая независимость) и не даёт сбиться;
- не стыдит за осознанные покупки — владелец живёт так, как хочет, вопрос только в балансе;
- помогает с инвестициями в рамках, описанных в разделе 7.

## 2. Цели, не-цели, анти-цели

**Цели**
- Недельная сводка в Telegram (3–5 строк + ссылка на подробный разбор).
- Сообщение в дни зарплаты: сколько пришло и сколько отложить по правилу.
- Месячный разбор — диалог в Claude Code; итог записывается в ретроспективу FinTree.
- Инвестиционный модуль (шаг 2): инвестиционная политика владельца и контроль её соблюдения.

**Не-цели**
- Функция FinTree для других пользователей (сейчас только личный инструмент).
- Лимиты по категориям, поштучный разбор покупок.
- Подбор конкретных инвестиционных инструментов и советы «купить/продать» (агент этого не делает никогда).
- Работа с инвестиционными данными FinTree до шага 2.

**Анти-цели** (провал, даже если всё «работает»)
- Агент ворчит и придирается — владелец перестаёт открывать сводки.
- Агент делает выводы-додумки («потеря на телевизоре», который на деле был заменой) вместо вопросов.
- Цифры в сводке посчитаны ИИ «на глаз» и расходятся с данными.
- Сводки пропадают (сломанная авторизация, выключенный Mac).
- Личные данные попадают в публичный репозиторий или облачному агенту выдаётся доступ к чужим данным.

## 3. Ограничения

- Проектные правила (`CLAUDE.md`): без EF-миграций; агент не запускает `dotnet build/test/run`; без коммитов
  без явного согласия; найденный техдолг — в `TODO.md`.
- Авторизация API сейчас — только JWT из cookie (`FinTree.Api/Program.cs:186-215`), refresh-токены
  ротируются (`FinTree.Application/Users/AuthService.cs:106-130`) → облачный агент не может держать сессию.
- Текущий пользователь берётся из claim `NameIdentifier` (`FinTree.Api/HttpCurrentUser.cs`).
- Бот сейчас только принимает сообщения (`FinTree.Infrastructure/Telegram/TelegramBotHostedService.cs`), но
  `TelegramBotClient` уже зарегистрирован; у пользователя есть `TelegramUserId` (`FinTree.Domain/Identity/User.cs:19`).
- Ретроспектива уже хранит «вывод», «план на месяц», «победы», «где сэкономить» и три оценки
  (`FinTree.Application/Retrospectives/RetrospectiveDtos.cs`) — это память советника между месяцами.
- Модель (Claude) не даёт персональных инвестиционных рекомендаций.

## 4. Рассмотренные подходы и выбор

**Доступ облачного агента к данным** — выбран вариант 1.
1. *Личный токен в FinTree* (выбран). Отдельная схема аутентификации: токен хранится хэшем в переменных
   окружения, привязан к пользователю, ограничен набором разрешений. Без таблиц и миграций.
   У облачного агента один секрет.
2. *Локальный запуск на Mac через Chrome* — отклонён: сводки пропадают при выключенном Mac или разлогине.
3. *Прямое чтение БД через SSH* — отклонён: облачный агент получает доступ к данным всех пользователей.

**Где читать и обсуждать** — выбран вариант 2.
1. *Всё в Telegram с ИИ-диалогом в боте* — отклонён: ИИ в боевом бэкенде, по сути продуктовая функция.
2. *Telegram — сигнал, Claude Code — разговор* (выбран).
3. *Только Claude Code* — отклонён: сводку легко пропустить.

**Мерка «хорошо/плохо»** — выбрана «сначала себе»: одно правило — доля зарплаты, которую нужно отложить
(значение в профиле). Альтернативы (лимиты по категориям; сравнение с собственной нормой без цели)
отклонены: первая ведёт к придиркам, вторая — к самооправданию. Используются только внутри, когда агент
ищет причину отставания.

**Учёт крупных покупок** — нарастающий итог от даты старта (из профиля), а не помесячно: крупная покупка
создаёт «долг перед собой» со сроком погашения, месяц без крупных трат его гасит. Отдельной копилки нет.

## 5. Поведение советника (решено с владельцем)

- **Ритм:** еженедельная сводка; сообщение в дни зарплаты (числа — в профиле); месячный разбор.
- **Главная цифра недели:** «сколько ещё можно потратить до конца месяца и остаться в цели»
  (с учётом ожидаемой выплаты; её размер оценивается по истории выплат).
- **Когда всё по плану:** вердикт + счётчик + максимум одно наблюдение в неделю, и только об устойчивом
  тренде (держится 2–3 месяца), не о разовом всплеске.
- **Когда план срывается:** факты + конкретное предложение в цифрах («чтобы закрыть N к дате, тратьте до X
  в неделю; сильнее всего выросло Y») + «решать вам». Без запретов.
- **Месячный разбор:** агент сверяет прошлые планы и объяснения из ретроспектив с фактом и кладёт рядом,
  не спорит. Сомнительное — спрашивает, а не додумывает. Итог (вывод, победы, план, где сэкономить,
  оценки) пишет в ретроспективу месяца.
- **Свобода в днях:** отклонение от цели переводится в «приблизил/отдалил финансовую независимость на N дней»
  по модели из профиля.
- **Подталкивать тратить** на здоровье, долголетие и объективный комфорт; путешествия и хобби не
  контролируются ничем, кроме общего правила.
- **Задачи вне трат** (страховка, налоговое резидентство и т. п. — список в профиле) — отдельный список с
  напоминаниями, не лимиты.
- **Испытательный срок:** пока он идёт, агент проверяет, что ликвидные деньги покрывают ≥ 6 месяцев трат.
- **Флаг «обязательная»** — только справочно; вердикт на нём не строится.
- **Тон:** простой русский, коротко, без нравоучений, вывод первой строкой.

## 6. Архитектура (шаг 1 — траты)

### 6.1 Бэкенд FinTree: личный токен
- Новая схема аутентификации (рядом с JWT), заголовок `Authorization: Bearer ftpat_<секрет>`.
- Конфиг из окружения: список `{ TokenHash (SHA-256), UserId, Scopes }`. Сравнение хэшей за постоянное время.
  Без БД → без миграций. Отзыв токена — удалить запись из окружения и перезапустить контейнер.
- Успешная аутентификация выдаёт claims как у обычного входа (`NameIdentifier` = UserId), плюс claim с scopes,
  чтобы существующие сервисы через `ICurrentUser` работали без изменений.
- Scopes:
  - `read` — GET: операции, категории, счета, аналитика, ретроспективы;
  - `retro:write` — создание/обновление ретроспективы;
  - `notify` — новый эндпоинт отправки сообщения себе в Telegram.
- Всё остальное для запросов с токеном запрещено (по умолчанию — deny для любых мутаций без явного scope).
- Новый эндпоинт: `POST /api/users/me/notify` `{ text, format }` → бот шлёт сообщение на `TelegramUserId`
  текущего пользователя. Ограничение длины (лимит Telegram 4096) и частоты.
- Секрет токена генерирует владелец; в репозиторий и логи не попадает.

### 6.2 Расчётный скрипт (детерминированный)
- Все цифры считает код, ИИ только объясняет. Скрипт берёт данные через API с токеном и печатает JSON с метриками.
- Метрики: доход и «отложено» с даты старта; цель и разрыв («долг перед собой»); срок погашения долга при
  текущем темпе; «можно ещё потратить до конца месяца»; траты недели против типичной недели;
  устойчивые тренды по категориям; «дни свободы»; покрытие ликвидными деньгами (в месяцах).
- База «типичной недели/месяца» — периоды с регулярным доходом (период без дохода исключается; границы — в
  конфиге профиля).
- Параметры (доля, дата старта, дни выплат, параметры модели независимости) приходят из конфига, а не из кода.

### 6.3 Навыки и запуск
- `fin-weekly` — облачная задача по расписанию раз в неделю: скрипт → текст → `notify`.
- `fin-payday` — облачная задача на следующий день после каждой выплаты (см. раздел 9).
- `fin-monthly-review` — локальный навык для диалога в Claude Code; читает полный профиль и ретроспективы,
  пишет итог в ретроспективу.
- Навыки и скрипт — в репозитории (в них нет личных данных). Личный конфиг облачных задач — в их настройках
  или секретах, не в репозитории. Полный профиль — только локально.

### 6.4 Подробный разбор (страница по ссылке)
- Предпочтительно — приватная страница-артефакт, обновляемая каждую неделю.
- Если из облачной задачи публиковать страницу нельзя — fallback: развёрнутый текст прямо в Telegram
  (свёрнутая цитата), без ссылки.

## 7. Инвестиционный модуль (шаг 2)

Агент — помощник, решения принимает владелец. Агент **не** подбирает инструменты и **не** советует купить/продать.

- **Инвестиционная политика** — документ, который пишет владелец: цель, горизонт, целевые доли по классам
  активов, правила пересмотра, «никогда не покупаю». Агент помогает вопросами. Хранится локально рядом с профилем.
- **Дни зарплаты:** сумма к откладыванию делится по долям из политики; пополнение считается так, чтобы
  выровнять отклонения.
- **Раз в месяц:** отклонение портфеля от целевых долей.
- **Обучение:** как устроены классы активов, риски, издержки, налоги (ИИС, жизнь в двух странах).
- **Факты по шорт-листу владельца:** комиссии, состав, ликвидность, налоги, валютный риск — таблицей.
- **Сценарии:** влияние предложенного владельцем распределения на срок до независимости и просадку в плохой год.
- **Журнал решений:** что и почему решено, чтобы через год сравнить.
- **Подбор под владельца** — к независимому финансовому советнику из реестра ЦБ; агент готовит сводку к встрече.

## 8. Известные проблемы данных (влияют на точность)

- Переводы между счетами не записываются → балансы счетов в FinTree неверны; покрытие ликвидными
  деньгами по данным FinTree ненадёжно.
- Инвестиционные данные в FinTree устарели.
- Неоднородные категории и флаги в истории (детали в профиле).

## 9. Решения автора дизайна (проверка «глазами строителя»)

- Цель считается от доходов категории «Зарплата» (аванс, остаток, премия). «Отложено» = все доходы − все
  расходы (продажа вещей, подарки, кэшбэк помогают закрыть разрыв, но не увеличивают цель).
- Все суммы — в базовой валюте (`amountInBaseCurrency`), переводы (`isTransfer`) исключаются.
- Выплата распознаётся по доходу категории «Зарплата»; `fin-payday` запускается на день позже дня выплаты
  и ищет выплату за последние 2 дня; если её нет — молчит (поздние выплаты покажет недельная сводка).
  Так задачи не нужно хранить состояние между запусками.
- Месячный разбор запускает владелец; последняя недельная сводка месяца напоминает о нём.
- Сборку и деплой бэкенда выполняет владелец (агенту запрещён `dotnet build`); переменные окружения
  токена добавляются в `compose.yaml` по образцу существующих секретов.

## 10. Остаётся решить

**Владельцу (шаг 2):**
- Откуда агент берёт актуальные позиции портфеля: FinTree хранит баланс по счёту, а не по бумагам.

**Строителю:**
- Язык расчётного скрипта (предпочтительно — без внешних зависимостей, чтобы работал в облачной задаче).
- Можно ли из облачной задачи публиковать страницу-артефакт и где хранить её секреты — проверить первым делом
  (пробный запуск), до основной разработки.
- Точный день и время недельной сводки (по умолчанию — понедельник утром по местному времени).
- Формат текста сводок в пределах раздела 5.

### Результаты пробного запуска облачной задачи (2026-11-16)

- Python в облаке — 3.11; ветки репозитория доступны через `git fetch`.
- Переменные `FINTREE_PAT` и `FIN_CONFIG_JSON` задаются в настройках окружения (формат `.env`, одна строка на
  переменную). Интерфейс предупреждает, что значения видят все пользователи окружения.
- Исходящая сеть ограничена allowlist'ом: запрос к сайту FinTree отклоняется прокси (`CONNECT 403`) — домен
  нужно добавить в разрешённые хосты окружения.
- Публикация приватной страницы (Artifact) из облачной задачи работает → подробный разбор можно отдавать ссылкой.
- Задача по умолчанию получает все подключённые коннекторы аккаунта; в промпте задач явно запрещено их использовать.
